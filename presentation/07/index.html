CBuilding blocks · 1 of 6

Context: what the model needs to know

What the model needs to know, and how to provide it: business context, rules and knowledge. When it arrives is the harness’s job.

One idea to keep

A model can only be as good as what it sees. Context is where your data, rules and know-how enter the system.

Context engineeringthe discipline: decide what the model should see
Contextthe runtime asset the harness draws on

What you have

Curate it: documents, databases, policies, the team’s know-how.

What you define

Engineer it: entity, memory and input/output schemas, rules, prompts and skills, how to retrieve.

  • Documents
  • RAG
  • Knowledge graphs
  • Memory schema
  • Entity schemas
  • Ontologies
TBuilding blocks · 2 of 6

Tools: extend what the model can do

Extend model capabilities: process data, fetch information and take actions in other systems.

One idea to keep

Connecting a model to tools does not make it smarter. It changes its reach, and with it, what can go wrong.

Tool1 capability: one function, one job
API · MCP server1–n capabilities: a reusable wrapper or proxy around tools

Read vs. act

Fetching data is low risk. Changing something, a refund or an email, needs limits.

Built-in vs. connected

Your own functions, or a server many apps reuse: N + M integrations, not N × M.

WBuilding blocks · Flows · 3 of 6

Workflows: the same path, every time

Coordinate multiple steps and actions to accomplish a goal. In a workflow, your code fixes the order of the steps; the model does the language inside them.

One idea to keep

A workflow follows the path you drew. Same input, same steps: easy to test, easy to explain.

Workflowfollows steps: code decides the path
Agentautonomy: the model decides the path

When to use

Known, repeatable tasks: classify, route, extract, draft then check.

Five common patterns

Chaining, routing, parallel, orchestrator-workers, evaluator-optimizer.

Patterns from Anthropic, Building effective agents (2024).

ABuilding blocks · Flows · 4 of 6

Agents: the model chooses the path

Coordinate multiple steps and actions to accomplish a goal. An agent works in a loop, think → act → observe, and decides the next step itself.

One idea to keep

An agent chooses its own path. More reach for open-ended tasks, and more to check.

Workflowfollows steps: code decides the path
Agentautonomy: the model decides the path

Agent vs. agentic

An agent is one loop that plans, uses tools and checks results. Agentic describes a whole system: agents and workflows with shared memory and controls.

Single- vs. multi-agent

One loop with a few tools: start here. Several specialists, coordinated by a lead or by handoffs, when one is not enough.

GBuilding blocks · 5 of 6

Guardrails: checks in code around the model

Validate and constrain system behavior: rules that run on every request, before, during and after the model.

One idea to keep

Asking the model to behave is not a control. Guardrails in code enforce the rule, whatever the model does.

Inputwhat is allowed in
Executionwhat it is allowed to do
Outputwhat is allowed out
  • Personal-data redaction
  • Prompt-injection detection
  • Tool access by role
  • Approval thresholds
  • Groundedness
  • Secret filter

Every guardrail has a cost: latency, false alarms and upkeep. Test them like the rest of the system.

EBuilding blocks · 6 of 6

Evals: evidence, not impressions

Assess quality, correctness, safety and task success: repeatable checks whose results you can compare over time.

One idea to keep

No eval, no evidence. Evals decide whether a change ships, which model to use, and whether a guardrail works.

Code checksfast and exact
LLM as a judgereads like a person
Human reviewthe reference

Before release

Regression tests and experiments on fixed cases, against a baseline.

In production

Samples of live traffic, judged and spot-checked by people.

Code first, a judge second, people to calibrate the judge.

Where you are

Six levels, L0 to L5

AI adoption isn’t binary. Like self-driving cars, it moves in levels, and the higher you go, the more the improvement cycles must run on their own.

Automating workflows Agents in your org
L0

AI as a Tool

Personal convenience; nothing reorganizes.

L1

Individual Automation

One person automates their own work.

L2

Team Automation

A team shares the workflow.

L3

Directed Autonomy

You point an agent across the company.

L4

Self-Directed Autonomy

The agent notices and proposes.

L5

Self-Driving Enterprise

The agent acts; humans govern.

No fully self-driving organization exists yet.

Adapted from Ann Miura-Ko (Floodgate), six levels of enterprise AI adoption, modelled on the SAE levels of driving automation.

To close

A GenAI system is never finished. It learns from experience: every interaction is evidence, and every validated change makes it better.

Models are trained once. Systems keep learning.
